# v6 实施与验证记录

日期：2026-10-06。基准：[PRD v6](PRD_CartBack_v6.md)。代码分支：`codex/conversation-v6`，保留当前工作区修改，未发布。

## 已实现

- 新前端会话显式选择 `flow_version:6`；历史会话继续使用原协议。数据库仅增加活动协议、业务版本和流程状态字段，保留 Python 实现。
- 新对话模块接受模型提出的 set/clear/propose/resolve。明确决定与候选分开保存，查询不推进业务版本，清空不被旧单调合并复活。
- 原因和目标可选；优惠未定和明确无优惠分开。取消泛化“折扣”默认 10% 的旧行为，不用追问计数代替用户决定。
- 服务器生成带对象和业务版本的语义按钮，前端提交操作 ID。初始采集无三个完成按钮；受众和优惠决定就绪且不存在相关未决候选时出现三个出口。
- 预览提前创建、持久化、编辑保存。用户明确选择模板的离线路径可以使用；模型失效保留原始消息，不猜活动信息。另有手动活动信息编辑入口。
- 准备操作明确提示建券副作用且不会发送。店铺未连接、建券失败、现有码无法校验时保留原优惠和预览。
- v6 草稿保存冻结受众 ID，未知条件不会回退全部客户，零匹配不会自动扩大名单。发送时继续执行退订、频控、时段和资源等原有检查。
- 发送批准绑定业务版本、实际文案、HTML、图片和受众 ID。旧版本无法发送；图片生成与发送互斥，生成图片推进业务版本。
- HTML 生成透传已审核预览，保持所有变体一致，不再悄悄生成另一版消费者文案。生成结果保留协议、版本、受众和编辑元数据。
- 高折扣保持商家选择，最终发送前按现有阈值单独确认风险。确认未通过不会编辑落库或排队。
- 长期资料通过明确候选批准或设置页管理。活动历史供显式复用，不自动变成长期偏好；单项限制删除保留其他限制，陈旧长期资料候选拒绝覆盖更新后的值。
- 刷新、切换会话和导览后恢复预览、资源失败原因和已准备方案；已准备的对话卡文案只读，编辑发送沿用邮件页明确操作。
- 批次运维沿用既有作用域、待确认和执行器，不随本次改造重写。

## 验证

后端 `npm test`：**340/340 通过**，包含 `pretest` TypeScript 构建。前端 `npm run build` 构建和类型检查通过，保留现有 lint 警告。`git diff --check` 通过。

v6 新增覆盖包括：可选信息、明确无优惠、未定优惠、多个候选、否定/暂缓、过期动作、SQLite 与 JSON 重启后的撤销、离线手动编辑、预览保存、未连接店铺、真实现有码校验入口、高折扣风险、固定受众范围、HTML 文案透传、图片/发送互斥，以及长期资料查看、编辑、按项删除和清空后的查询。

结构化模型回放使用脚本化提议经过实际对话模块和持久化路径；这是确定性集成验证，**不是真实模型成功率评估**。旧四槽、单调填充和关键词兜底断言继续只测试历史协议，新协议有独立验收。

独立审查指出的 HTML 重写、元数据丢失、现有码被忽略和图片竞态已修复并添加回归覆盖。“准备后仍可编辑对话预览”的报告经复核不成立：S3 不发布 save_preview 操作，组件在该状态显示只读文案；测试亦断言 S3 不存在此操作。

## 当前能力边界

本轮审查修复：无优惠恢复先保存中性预览，保留 S2，核对后才准备草稿；店铺返回的真实优惠码替换预览占位符或补充结账说明，并同步到卡片、草稿、全部变体和 HTML，文案变化推进业务版本；客单价写入统一使用「客单价」，读取兼容历史 `aov`，优先使用最新记录。回归测试覆盖三个 HTTP 场景、客单价候选确认/撤销、旧记录兼容和前端预览状态。

后续审查修复：受众页现有「弃购 / 下单未付客户」「沉睡 / 流失老客」快捷标签按原前端分组语义解析，附加国家条件仍生效，未知筛选条件仍拒绝执行；创建会话的 HTTP 失败和无效响应在更新界面前抛出，由原有错误处理保留当前会话并展示原因。新增测试覆盖实际前端标签、附加筛选、未知条件及 409/500 创建失败。

- 受众确定性解析支持已有行为组、年龄范围、性别、七个已映射国家及明确全部受众。日期、商品购买历史等无法由当前数据可靠求值的条件会阻断执行，仍可聊天和写预览；没有擅自删条件或扩大名单。
- 当前店铺执行器支持百分比折扣码与无优惠。免邮、赠品和满减资源保留选择，但准备时说明尚不支持，不能伪装履约成功。
- 单次发送在时段外可直接批准并预约下一合理时段；批次排程仍由原批次执行器管理。
- 未进行生产部署、真实模型对比评估或真实店铺/ESP 发信验证。发布前仍需在目标环境验证供应商连接、实际模型语义效果与真实渲染交付。
- 当前工作区含本次之前的流程、记忆和发送修复，以及用户其他未提交资料；未覆盖或删除这些资料。

## 发送体验调整

按用户明确要求，退订链接配置错误暂时不在方案卡展示，也不拦截发送；后端保留实际检测结果并标记 `blocking:false`，已退订名单过滤和配置后的退订链接/邮件头仍按原逻辑执行。时段外显示「定时发送」，确认后写入现有队列的 `run_after` 和草稿的 `scheduled_at`，到点重新检查执行条件。方案卡与邮件编辑页采用同一可发送状态计算，频控、署名、金额和优惠码问题仍作为阻断项。

已验证退订配置缺失时的仿真投递、与时段外条件同时出现时的预约队列，以及前端隐藏/定时状态。前端共用开发服务器 `.next` 的构建发生文件缺失，独立临时目录完整构建通过；当前工作区 `tsc --noEmit --incremental false` 通过。保留现有字体、img 和 Hook lint 警告。

## GUI 报告对应修复

- 生成预览中的百分比、中文折扣和免邮承诺与当前优惠比较；发生明显漂移时按当前品牌、商品、邮件语种和优惠生成事实一致的预览，展示修正原因。优惠码使用占位符，准备后绑定店铺真实回执。
- 默认图片提示词只负责商品与场景，不让模型绘制优惠、文字或配送承诺。无优惠时本地叠字也跳过，商品与品类通过卡片、草稿和图片重生成链路保留。历史图片不会被代码修改自动重画，需重新生成。
- 邮件编辑保存新增独立 PUT 接口，保存主题、正文、变体和本地渲染 HTML；业务版本推进，旧发送批准失效。前端等待成功响应后才返回预览，失败保留编辑内容并显示原因。
- 明确的「先不放优惠吧」可直接保存无优惠；咨询仍为候选，已有候选不阻止回答其他问题。高折扣保持选择，并立即说明利润影响，最终发送仍按原风险确认处理。
- 常见加购未付款/未结账说法可解析；未知附加条件仍不被丢弃。准备失败在卡片保留原因与修复路径。
- 上一版预览保留为失效内容供查看；当前版本需重新核对。会话编号按创建顺序显示，切换后清除旧 toast，隐藏的 toast 不留在 DOM。准备期间显示耗时与过程说明。
- 邮件语种继续按店铺设置，预览明确展示当前语种；不根据商家聊天语言擅自改变收件人文案语言。
- Next 开发输出改为 `.next-dev`，生产构建使用 `.next`，避免 manifest 相互覆盖。当前前端 3100 与后端 4173 健康检查均返回 200。
